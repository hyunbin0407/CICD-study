# 2회차 실습 · 첫 워크플로우 직접 만들기 (명령어 따라하기)

> 개념 설명은 [`README.md`](./README.md). 이 문서는 **터미널에 그대로 붙여넣어 진행**하는 실습입니다.
> 미션마다 `① 파일 작성 → ② 커밋 & push → ③ 실행 & 확인` 3단계를 반복합니다.
> 완성본은 [`solution.yml`](./solution.yml) 과 비교하세요.

## 준비 (한 번만)

```bash
# 저장소 루트로 이동 (경로는 본인 환경에 맞게)
cd ~/Workspace/CICD-study

# 최신 상태로 맞추기
git checkout main
git pull origin main

# 워크플로우 폴더 생성 (이미 있으면 그냥 넘어감)

# gh CLI 로그인 확인 (아래처럼 계정이 뜨면 OK)
gh auth status
```

> 이 실습은 결과 확인을 GitHub 웹 대신 `gh`(GitHub CLI)로 합니다.
> 웹에서 보고 싶으면 언제든 저장소 → **Actions** 탭을 열어도 됩니다.

## 미션 1 · 수동 실행되는 워크플로우 만들기

**배우는 것:** `name` / `on: workflow_dispatch` / job 1개 / `run` step

### ① 파일 작성

```bash
cat > .github/workflows/hello.yml <<'EOF'
name: My First Workflow

on:
  workflow_dispatch:        # Actions 탭 / gh 명령으로 수동 실행

jobs:
  hello:
    runs-on: ubuntu-latest  # 이 job이 도는 러너(가상 머신)
    steps:
      - name: 인사 출력
        run: echo "첫 번째 워크플로우 실행됨"
EOF
```

### ② 커밋 & push

```bash
git add .github/workflows/hello.yml
git commit -m "2회차 미션1: 첫 워크플로우 (수동 실행)"
git push origin main
```

### ③ 실행 & 확인

```bash
# 수동 트리거 실행
gh workflow run hello.yml --ref main

# 방금 만든 실행이 목록에 뜰 때까지 잠깐 기다렸다가 확인
sleep 5
gh run list --workflow hello.yml

# 가장 최근 실행을 실시간으로 따라가기 (끝나면 결과 요약)
gh run watch "$(gh run list --workflow hello.yml -L1 --json databaseId -q '.[0].databaseId')"

# 로그 전체 보기
gh run view "$(gh run list --workflow hello.yml -L1 --json databaseId -q '.[0].databaseId')" --log
```

**확인 포인트**
- [ ] `gh run list` 에 `My First Workflow` 실행이 `completed / success` 로 보인다
- [ ] `--log` 출력에 `첫 번째 워크플로우 실행됨` 문구가 있다
- [ ] push만 했을 때는 실행이 안 생기고, `gh workflow run` 을 해야 생긴다 (= `workflow_dispatch` 의 의미)

## 미션 2 · push 될 때 자동 실행되게 하기

**배우는 것:** `on: push` + `paths` 필터

### ① 파일 작성 (덮어쓰기)

```bash
cat > .github/workflows/hello.yml <<'EOF'
name: My First Workflow

on:
  workflow_dispatch:
  push:
    paths:                              # 이 경로가 바뀐 커밋에서만 실행
      - "02-first-workflow/**"
      - ".github/workflows/hello.yml"

jobs:
  hello:
    runs-on: ubuntu-latest
    steps:
      - name: 인사 출력
        run: echo "첫 번째 워크플로우 실행됨"
EOF
```

### ② 커밋 & push

```bash
git add .github/workflows/hello.yml
git commit -m "2회차 미션2: push 트리거 + paths 필터 추가"
git push origin main
```

### ③ 실행 & 확인

```bash
# 이번엔 gh workflow run 없이, push 만으로 실행이 생겼는지 확인
sleep 5
gh run list --workflow hello.yml -L5

# 최근 실행의 트리거(event)가 push 인지 확인
gh run view "$(gh run list --workflow hello.yml -L1 --json databaseId -q '.[0].databaseId')" --json event,displayTitle,status,conclusion
```

**확인 포인트**
- [ ] `gh workflow run` 을 안 했는데도 push 직후 새 실행이 생겼다
- [ ] 그 실행의 `event` 값이 `"push"` 다
- [ ] (실험) 필터 밖 파일(루트 README)만 고쳐서 push 하면 → 이 워크플로우는 실행되지 않는다
  ```bash
  # 저장소 루트에서 실행
  printf '\n<!-- paths 필터 테스트 -->\n' >> README.md
  git add README.md && git commit -m "테스트: 필터 밖 파일 변경" && git push origin main
  sleep 5
  gh run list --workflow hello.yml -L3      # 새 실행이 안 늘어남 (개수 그대로)
  git revert --no-edit HEAD && git push origin main   # 되돌리기
  ```

## 미션 3 · 코드 체크아웃 + 실행 정보 출력

**배우는 것:** `uses`(재사용 액션), `${{ github.* }}` 컨텍스트, 여러 줄 `run`

### ① 파일 작성 (덮어쓰기)

```bash
cat > .github/workflows/hello.yml <<'EOF'
name: My First Workflow

on:
  workflow_dispatch:
  push:
    paths:
      - "02-first-workflow/**"
      - ".github/workflows/hello.yml"

jobs:
  hello:
    runs-on: ubuntu-latest
    steps:
      - name: 코드 체크아웃
        uses: actions/checkout@v4        # 저장소 파일을 러너로 가져옴

      - name: 실행 정보 출력
        run: |
          echo "실행한 사람: ${{ github.actor }}"
          echo "트리거 이벤트: ${{ github.event_name }}"
          echo "브랜치: ${{ github.ref_name }}"
          echo "커밋 SHA: ${{ github.sha }}"

      - name: 파일 목록
        run: ls -al
EOF
```

### ② 커밋 & push

```bash
git add .github/workflows/hello.yml
git commit -m "2회차 미션3: checkout + 컨텍스트 출력"
git push origin main
```

### ③ 실행 & 확인

```bash
sleep 5
RUN_ID="$(gh run list --workflow hello.yml -L1 --json databaseId -q '.[0].databaseId')"
gh run watch "$RUN_ID"
gh run view "$RUN_ID" --log
```

**확인 포인트**
- [ ] `파일 목록` step의 `ls -al` 결과에 `README.md`, `01-what-is-cicd` 등 저장소 파일이 보인다
- [ ] `트리거 이벤트` 가 `push` 로 찍힌다
- [ ] (실험) `uses: actions/checkout@v4` step을 지우고 push 하면 → `ls -al` 에 저장소 파일이 없다 (확인 후 다시 추가)

## 미션 4 · step 실패 동작 관찰하기

**배우는 것:** 한 step이 실패하면 이후 step은 실행되지 않는다(skip)

### ① 파일 작성 — `파일 목록` step 앞에 일부러 실패하는 step 추가

```bash
cat > .github/workflows/hello.yml <<'EOF'
name: My First Workflow

on:
  workflow_dispatch:
  push:
    paths:
      - "02-first-workflow/**"
      - ".github/workflows/hello.yml"

jobs:
  hello:
    runs-on: ubuntu-latest
    steps:
      - name: 코드 체크아웃
        uses: actions/checkout@v4

      - name: 실행 정보 출력
        run: |
          echo "실행한 사람: ${{ github.actor }}"
          echo "트리거 이벤트: ${{ github.event_name }}"
          echo "브랜치: ${{ github.ref_name }}"

      - name: 일부러 실패시키기
        run: exit 1

      - name: 파일 목록
        run: ls -al
EOF
```

### ② 커밋 & push

```bash
git add .github/workflows/hello.yml
git commit -m "2회차 미션4: 실패 step 동작 관찰"
git push origin main
```

### ③ 실행 & 확인

```bash
sleep 5
RUN_ID="$(gh run list --workflow hello.yml -L1 --json databaseId -q '.[0].databaseId')"
gh run watch "$RUN_ID" || true          # 실패로 끝나므로 || true 로 명령 자체는 통과
gh run view "$RUN_ID"                    # step별 성공/실패/skip 표시 확인
```

**확인 포인트**
- [ ] `일부러 실패시키기` step에 X(실패) 표시
- [ ] 그 **뒤의 `파일 목록` step은 실행되지 않음** (`-` 또는 skipped 표시)
- [ ] job 전체 결론(`conclusion`)이 `failure`
- [ ] 관찰 내용을 [`README.md`](./README.md) "8. 배운 점" 아래에 2~3줄 메모

### ④ 원상복구 (실패 step 제거)

```bash
cat > .github/workflows/hello.yml <<'EOF'
name: My First Workflow

on:
  workflow_dispatch:

    paths:
      - "02-first-workflow/**"

  hello:
    runs-on: ubuntu-latest
    steps:
      - name: 코드 체크아웃
        uses: actions/checkout@v4

      - name: 실행 정보 출력
        run: |
          echo "실행한 사람: ${{ github.actor }}"
          echo "트리거 이벤트: ${{ github.event_name }}"
          echo "브랜치: ${{ github.ref_name }}"

      - name: 파일 목록

git add .github/workflows/hello.yml
```

## 미션 5 · 두 번째 job을 순서대로 실행하기

**배우는 것:** `needs` 로 job 실행 순서 제어 (job은 기본 병렬)

### ① 파일 작성 (덮어쓰기) — `done` job 추가

```bash
cat > .github/workflows/hello.yml <<'EOF'
name: My First Workflow

on:
  workflow_dispatch:
  push:
    paths:
      - "02-first-workflow/**"
      - ".github/workflows/hello.yml"

jobs:
  hello:
    runs-on: ubuntu-latest
    steps:
      - name: 코드 체크아웃
        uses: actions/checkout@v4

      - name: 실행 정보 출력
        run: |
          echo "실행한 사람: ${{ github.actor }}"
          echo "트리거 이벤트: ${{ github.event_name }}"
          echo "브랜치: ${{ github.ref_name }}"

      - name: 파일 목록
        run: ls -al

  done:
    runs-on: ubuntu-latest
    needs: hello                 # hello job이 성공해야 시작
    steps:
      - name: 완료 알림
        run: echo "hello job이 끝나서 done job 실행됨"
EOF
```

### ② 커밋 & push

```bash
git add .github/workflows/hello.yml
git commit -m "2회차 미션5: needs 로 job 순서 만들기"
git push origin main
```

### ③ 실행 & 확인

```bash
sleep 5
RUN_ID="$(gh run list --workflow hello.yml -L1 --json databaseId -q '.[0].databaseId')"
gh run watch "$RUN_ID"

# 각 job의 시작/종료 시각으로 순서 확인 (hello 가 끝난 뒤 done 이 시작됨)
gh run view "$RUN_ID" --json jobs -q '.jobs[] | {name, status, conclusion, startedAt, completedAt}'
```

**확인 포인트**
- [ ] `hello` 의 `completedAt` 이 `done` 의 `startedAt` 보다 빠르다 (= 순서대로 실행됨)
- [ ] `gh run watch` 중 `hello` 가 도는 동안 `done` 은 대기 상태다
- [ ] (실험) `needs: hello` 줄을 지우고 push 하면 두 job의 `startedAt` 이 거의 같아진다 (= 병렬)

## 도전 미션 (선택) · 같은 job을 여러 버전에서 실행

> 8회차(매트릭스 빌드) 예고편. 건너뛰어도 됩니다.

`hello` job 의 `runs-on:` 아래에 `strategy` 를 추가:

```yaml
  hello:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node: [16, 18, 20]
    steps:
      - name: 버전 출력
        run: |
          echo "Node 버전 후보: ${{ matrix.node }}"
```

> ⚠️ `run:` 을 한 줄로 쓰면서 문자열 안에 `콜론+공백`(`후보: `)이 있으면
> YAML이 `key: value` 로 오해해서 **파싱 에러**가 난다. `run: |` (리터럴 블록)으로 쓰면 안전.

push 후 `gh run view "$RUN_ID"` 에서 `hello (16)`, `hello (18)`, `hello (20)` 3개가 병렬로 도는지 확인.

### 자주 쓰는 gh 명령 요약

| 명령 | 용도 |
|---|---|
| `gh workflow run hello.yml --ref main` | 수동 실행 |
| `gh run list --workflow hello.yml` | 실행 이력 |
| `gh run watch <RUN_ID>` | 실시간 진행 추적 |
| `gh run view <RUN_ID> --log` | 전체 로그 |
| `gh run view <RUN_ID> --json jobs -q ...` | job별 상세(JSON) |
| `gh run view <RUN_ID> --web` | 브라우저로 열기 |

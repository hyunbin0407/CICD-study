## 미션 2 · 테스트를 CI에 붙이기

**배우는 것:** `checkout → setup-node → npm ci → npm test` 표준 순서

### ① 워크플로우 파일 작성

```bash
cat > .github/workflows/03-test.yml <<'EOF'
name: 03 - CI Test

on:
  workflow_dispatch:
  push:
    paths:
      - "03-auto-test/app/**"
      - ".github/workflows/03-test.yml"
  pull_request:
    paths:
      - "03-auto-test/app/**"
      - ".github/workflows/03-test.yml"

defaults:
  run:
    working-directory: 03-auto-test/app   # run: 스텝은 앱 폴더에서 실행

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - name: 코드 체크아웃
        uses: actions/checkout@v4

      - name: Node.js 설치
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
          cache-dependency-path: 03-auto-test/app/package-lock.json

      - name: 의존성 설치 (lockfile 그대로)
        run: npm ci

      - name: 테스트 실행
        run: npm test
EOF
```

### ② 커밋 & push

```bash
git add .github/workflows/03-test.yml
git commit -m "3회차 미션2: 자동 테스트 CI 워크플로우 추가"
git push origin main
```

### ③ 실행 & 확인

```bash
sleep 5
RUN_ID="$(gh run list --workflow 03-test.yml -L1 --json databaseId -q '.[0].databaseId')"
gh run watch "$RUN_ID"
gh run view "$RUN_ID" --log | grep -E "Tests:|npm ci|added [0-9]+ packages|Cache (saved|restored|not found)"
```

**확인 포인트**
- [ ] job `test` 가 `success`
- [ ] 로그에 `npm ci` → `added 267 packages` 비슷한 줄
- [ ] 로그에 `Tests: 10 passed, 10 total`
- [ ] `Cache` 관련 줄: 첫 실행이면 `Cache not found` + 끝에 저장. (두 번째 실행부터 `Cache restored`)

> 두 번째로 확인하고 싶으면 아무 것도 안 바꾸고 `gh workflow run 03-test.yml --ref main` 후 다시 로그를 보면
> `Cache restored` 로 바뀌고 `npm ci` 가 빨라진 걸 볼 수 있다.

## 미션 3 · 일부러 테스트 깨뜨리기 (CI가 빨개지는 것 보기)

**배우는 것:** 소스 버그 → 테스트 실패 → job 실패 → (PR이면) 머지 차단

### ① 소스에 버그 심기

`splitBill` 의 올림(`Math.ceil`)을 내림(`Math.floor`)으로 바꾼다:

```bash
perl -pi -e 's/Math\.ceil\(total \/ people\)/Math.floor(total \/ people)/' 03-auto-test/app/src/money.js
git diff 03-auto-test/app/src/money.js      # 한 줄 바뀐 것 확인
```

### ② 커밋 & push

```bash
git add 03-auto-test/app/src/money.js
git commit -m "3회차 미션3: (일부러) splitBill 버그 - 올림을 내림으로"
git push origin main
```

### ③ 실행 & 확인

```bash
sleep 5
RUN_ID="$(gh run list --workflow 03-test.yml -L1 --json databaseId -q '.[0].databaseId')"
gh run watch "$RUN_ID" || true
gh run view "$RUN_ID" --log-failed
```

**확인 포인트**
- [ ] job `test` 가 `failure`
- [ ] `테스트 실행` step이 `X`
- [ ] `--log-failed` 출력에 이런 식의 실패가 보인다:
  ```
  ● splitBill › 나머지가 있으면 올림한다
    expect(received).toBe(expected)
    Expected: 3334
    Received: 3333
  ```
- [ ] `Test Suites: 1 failed`, `Tests: 1 failed, 9 passed`

### ④ 버그 되돌리기

```bash
git revert --no-edit HEAD          # 방금 버그 커밋을 되돌리는 새 커밋
git push origin main

sleep 5
RUN_ID="$(gh run list --workflow 03-test.yml -L1 --json databaseId -q '.[0].databaseId')"
gh run watch "$RUN_ID"             # 다시 success 확인
```

- [ ] revert 후 CI가 다시 `success`

## 미션 4 · PR에서 테스트가 머지를 막는 것 체험

**배우는 것:** `on: pull_request` → PR 화면의 상태 체크 → 빨간 X면 머지 위험 신호

### ① 새 브랜치에서 버그 심기

```bash
git checkout -b practice/ci-on-pr
perl -pi -e 's/Math\.ceil\(total \/ people\)/Math.floor(total \/ people)/' 03-auto-test/app/src/money.js
git add 03-auto-test/app/src/money.js
git commit -m "practice: splitBill 버그 (PR 체크 확인용)"
git push -u origin practice/ci-on-pr
```

### ② PR 생성

```bash
gh pr create --fill                 # 제목/본문을 커밋에서 자동 채움
PR_URL="$(gh pr view --json url -q .url)"
echo "$PR_URL"
```

### ③ PR 체크 확인 (실패해야 정상)

```bash
sleep 10
gh pr checks                        # 03 - CI Test 가 fail 로 뜸
gh pr view                          # "Checks failing" 표시
```

**확인 포인트**
- [ ] `gh pr checks` 에 `03 - CI Test` 가 `fail` (또는 `X`)
- [ ] `gh pr view` 상단에 체크 실패 표시
- [ ] (웹으로 보기) `gh pr view --web` → PR 하단 "All checks have failed", Merge 버튼이 빨갛게 경고

### ④ 브랜치에서 고치면 체크가 다시 돈다

```bash
perl -pi -e 's/Math\.floor\(total \/ people\)/Math.ceil(total \/ people)/' 03-auto-test/app/src/money.js
git add 03-auto-test/app/src/money.js
git commit -m "practice: 버그 수정"
git push

sleep 10
gh pr checks                        # 이번엔 pass
```

- [ ] push 하자마자 PR 체크가 자동으로 다시 실행됨
- [ ] `gh pr checks` 가 `pass` 로 바뀜

### ⑤ 정리 (PR 닫고 브랜치 삭제)

이 PR은 연습용이라 머지할 내용이 없다 (버그 넣고 뺐으니 net 변화 0). 그냥 닫는다:

```bash
gh pr close practice/ci-on-pr --delete-branch
git checkout main
git pull origin main
```

- [ ] `gh pr list` 에 열린 PR 없음
- [ ] 로컬이 `main` 이고 최신 상태

> 실무에서는 여기서 "닫기" 대신 리뷰 받고 `gh pr merge` 로 머지한다.
> 그리고 Settings → Branches 에서 "Require status checks" 를 켜두면 빨간 체크일 때 머지 버튼 자체가 막힌다.

## 도전 미션 (선택) · Node 여러 버전에서 테스트

> 2회차 도전(matrix)의 실전판. 8회차에서 더 깊게 다룸.

`.github/workflows/03-test.yml` 의 `test` job 을 이렇게 바꾼다 (matrix + node-version 참조):

```bash
cat > .github/workflows/03-test.yml <<'EOF'
name: 03 - CI Test

on:
  workflow_dispatch:
  push:
    paths:
      - "03-auto-test/app/**"
      - ".github/workflows/03-test.yml"
  pull_request:
    paths:
      - "03-auto-test/app/**"
      - ".github/workflows/03-test.yml"

defaults:
  run:
    working-directory: 03-auto-test/app

jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node: [18, 20, 22]
    steps:
      - name: 코드 체크아웃
        uses: actions/checkout@v4

      - name: Node.js ${{ matrix.node }} 설치
        uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node }}
          cache: npm
          cache-dependency-path: 03-auto-test/app/package-lock.json

      - name: 의존성 설치
        run: npm ci

      - name: 테스트 실행
        run: npm test
EOF

git add .github/workflows/03-test.yml
git commit -m "3회차 도전: Node 18/20/22 매트릭스 테스트"
git push origin main

sleep 5
RUN_ID="$(gh run list --workflow 03-test.yml -L1 --json databaseId -q '.[0].databaseId')"
gh run watch "$RUN_ID"
gh run view "$RUN_ID" --json jobs -q '.jobs[] | "\(.name) → \(.conclusion)"'
```

**확인 포인트**
- [ ] `test (18)`, `test (20)`, `test (22)` 3개가 병렬로 돌고 전부 `success`
- [ ] 배지는 그대로 passing (matrix 전부 통과해야 초록)

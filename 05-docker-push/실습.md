## 준비 (한 번만) · Docker Hub Access Token + Secrets 등록

### ① Docker Hub Access Token 발급 (웹에서, 여기만 직접)

1. https://hub.docker.com 로그인 (계정: `gusqls0718`)
2. 우측 상단 계정 아이콘 → **Account Settings**
3. 왼쪽 메뉴 **Security** → **New Access Token**
4. Description: `cicd-study-ci` (아무 이름) / Access permissions: **Read & Write**
5. **Generate** → 나온 토큰 문자열을 복사 (이 화면을 닫으면 다시 못 봄)

### ② GitHub에 등록 — 사용자명은 Variable, 토큰은 Secret

```bash
cd ~/Workspace/CICD-study
git checkout main
git pull origin main

# 사용자명은 안 민감하니 Variable
gh variable set DOCKERHUB_USERNAME --body "gusqls0718"

# 토큰은 Secret. --body 없이 실행하면 gh가 자체적으로 안전한 프롬프트를 띄운다
# (입력값이 화면에 *로 가려지고, 쉘 히스토리에도 안 남음 — bash/zsh 둘 다 동일하게 동작)
gh secret set DOCKERHUB_TOKEN
# → "? Paste your secret:" 프롬프트가 뜨면 토큰을 붙여넣고 Enter

# 등록 확인 (값은 안 보이고 이름 + 갱신 시각만)
gh variable list
gh secret list
```

**확인 포인트**
- [ ] `gh variable list` 에 `DOCKERHUB_USERNAME` 이 값(`gusqls0718`)과 함께 보인다 (Variable은 값도 보임)
- [ ] `gh secret list` 에 `DOCKERHUB_TOKEN` 이 이름만 보인다 (값은 절대 안 보임)

## 미션 1 · 로그인만 되는지 최소 워크플로우로 확인

**배우는 것:** `docker/login-action`, Secrets/Variables 를 워크플로우에서 참조하기

빌드까지 한 번에 만들지 않고, **로그인 하나만** 먼저 검증한다 (문제가 생기면 원인을 좁히기 쉽도록).

### ① 파일 작성

```bash
mkdir -p .github/workflows
cat > .github/workflows/05-docker-push.yml <<'EOF'
name: 05 - Docker Push

on:
  workflow_dispatch:

jobs:
  login-test:
    runs-on: ubuntu-latest
    steps:
      - name: Docker Hub 로그인 테스트
        uses: docker/login-action@v3
        with:
          username: ${{ vars.DOCKERHUB_USERNAME }}
          password: ${{ secrets.DOCKERHUB_TOKEN }}
EOF
```

### ② 커밋 & push

```bash
git add .github/workflows/05-docker-push.yml
git commit -m "5회차 미션1: Docker Hub 로그인 테스트"
git push origin main
```

### ③ 실행 & 확인

```bash
gh workflow run 05-docker-push.yml --ref main
sleep 5
RUN_ID="$(gh run list --workflow 05-docker-push.yml -L1 --json databaseId -q '.[0].databaseId')"
gh run watch "$RUN_ID"
gh run view "$RUN_ID" --log | grep -i "login"
```

**확인 포인트**
- [ ] 로그에 `Login Succeeded`
- [ ] job `success`

<details><summary>힌트: 로그인이 실패하면</summary>

`unauthorized: incorrect username or password` 가 뜨면:
- `gh variable list` / `gh secret list` 에 이름이 정확히 `DOCKERHUB_USERNAME` / `DOCKERHUB_TOKEN` 인지
- 토큰이 아니라 계정 비밀번호를 넣은 건 아닌지 (토큰은 Docker Hub Access Token 화면에서 발급한 문자열)
- 다시 등록: `gh secret set DOCKERHUB_TOKEN` 으로 덮어쓰기(재실행하면 다시 값 입력받음)
</details>

## 미션 2 · 빌드 + Docker Hub push

**배우는 것:** 이미지 네이밍 규칙(`docker.io/사용자명/저장소:태그`), `push: true`, PR 트리거 추가

### ① 파일 작성 (덮어쓰기)

```bash
cat > .github/workflows/05-docker-push.yml <<'EOF'
name: 05 - Docker Push

on:
  workflow_dispatch:
  push:
    branches:
      - main
    paths:
      - "04-docker-build/app/**"
      - ".github/workflows/05-docker-push.yml"
  pull_request:
    paths:
      - "04-docker-build/app/**"
      - ".github/workflows/05-docker-push.yml"

jobs:
  docker-push:
    runs-on: ubuntu-latest
    steps:
      - name: 코드 체크아웃
        uses: actions/checkout@v4

      - name: Buildx 준비
        uses: docker/setup-buildx-action@v3

      - name: Docker Hub 로그인 (PR에는 안 함)
        if: github.event_name != 'pull_request'
        uses: docker/login-action@v3
        with:
          username: ${{ vars.DOCKERHUB_USERNAME }}
          password: ${{ secrets.DOCKERHUB_TOKEN }}

      - name: 이미지 빌드 (+ push는 PR에는 안 함)
        uses: docker/build-push-action@v6
        with:
          context: ./04-docker-build/app
          push: ${{ github.event_name != 'pull_request' }}
          tags: |
            docker.io/${{ vars.DOCKERHUB_USERNAME }}/cicd-study-sample:latest
            docker.io/${{ vars.DOCKERHUB_USERNAME }}/cicd-study-sample:${{ github.sha }}
          cache-from: type=gha
          cache-to: type=gha,mode=max
EOF
```

### ② 커밋 & push

```bash
git add .github/workflows/05-docker-push.yml
git commit -m "5회차 미션2: 이미지 빌드 + Docker Hub push"
git push origin main
```

### ③ 실행 & 확인

```bash
sleep 5
RUN_ID="$(gh run list --workflow 05-docker-push.yml -L1 --json databaseId -q '.[0].databaseId')"
gh run watch "$RUN_ID"
gh run view "$RUN_ID" --log | grep -Ei "pushing|digest|Login Succeeded"
```

**확인 포인트**
- [ ] `Login Succeeded`
- [ ] `pushing` / `digest: sha256:...` 로그 (레지스트리로 올라감)
- [ ] job `success`
- [ ] 브라우저로 https://hub.docker.com/r/gusqls0718/cicd-study-sample 열어보면 방금 push된 이미지가 보임

## 미션 3-보강 · 멀티 아키텍처(amd64 + arm64) 빌드

**배우는 것:** CI 러너(amd64)와 Apple Silicon 맥(arm64)의 아키텍처 차이, `docker/setup-qemu-action`, `platforms:`

방금 로컬에서 `docker pull` 이 `no matching manifest` 로 실패한 이유는 README 10절 참고 — 러너가 amd64라
amd64 이미지만 push됐기 때문. QEMU 에뮬레이터를 등록하고 `platforms:` 를 지정해서 두 아키텍처를 한 번에 빌드한다.

### ① 파일 작성 (덮어쓰기) — QEMU 설정 + `platforms` 추가

```bash
cat > .github/workflows/05-docker-push.yml <<'EOF'
name: 05 - Docker Push

on:
  workflow_dispatch:
  push:
    branches:
      - main
    paths:
      - "04-docker-build/app/**"
      - ".github/workflows/05-docker-push.yml"
  pull_request:
    paths:
      - "04-docker-build/app/**"
      - ".github/workflows/05-docker-push.yml"

jobs:
  docker-push:
    runs-on: ubuntu-latest
    steps:
      - name: 코드 체크아웃
        uses: actions/checkout@v4

      - name: QEMU 설정 (멀티 아키텍처 빌드용)
        uses: docker/setup-qemu-action@v3

      - name: Buildx 준비
        uses: docker/setup-buildx-action@v3

      - name: Docker Hub 로그인 (PR에는 안 함)
        if: github.event_name != 'pull_request'
        uses: docker/login-action@v3
        with:
          username: ${{ vars.DOCKERHUB_USERNAME }}
          password: ${{ secrets.DOCKERHUB_TOKEN }}

      - name: 이미지 빌드 (+ push는 PR에는 안 함)
        uses: docker/build-push-action@v6
        with:
          context: ./04-docker-build/app
          platforms: linux/amd64,linux/arm64
          push: ${{ github.event_name != 'pull_request' }}
          tags: |
            docker.io/${{ vars.DOCKERHUB_USERNAME }}/cicd-study-sample:latest
            docker.io/${{ vars.DOCKERHUB_USERNAME }}/cicd-study-sample:${{ github.sha }}
          cache-from: type=gha
          cache-to: type=gha,mode=max

      - name: push된 이미지 pull 검증 (PR에는 안 함)
        if: github.event_name != 'pull_request'
        run: |
          docker pull docker.io/${{ vars.DOCKERHUB_USERNAME }}/cicd-study-sample:latest
          docker run --rm docker.io/${{ vars.DOCKERHUB_USERNAME }}/cicd-study-sample:latest 30000 4 | tee out.txt
          grep "1인당" out.txt
EOF

git add .github/workflows/05-docker-push.yml
git commit -m "5회차 미션3-보강: 멀티 아키텍처(amd64+arm64) 빌드"
git push origin main
```

### ② CI에서 확인

```bash
sleep 5
RUN_ID="$(gh run list --workflow 05-docker-push.yml -L1 --json databaseId -q '.[0].databaseId')"
gh run watch "$RUN_ID"
gh run view "$RUN_ID" --log | grep -Ei "platform|linux/arm64|linux/amd64" | head -20
```

### ③ 로컬 맥에서 다시 검증 (이번엔 `--platform` 없이)


**확인 포인트**
- [ ] 빌드 로그에 `linux/amd64`, `linux/arm64` 두 플랫폼 빌드 흔적이 보임 (아까보다 로그·시간이 늘어남)
- [ ] 이번엔 `--platform` 없이도 `docker pull`/`docker run` 이 에러 없이 됨
- [ ] `docker image inspect ... --format '{{.Os}}/{{.Architecture}}'` 결과가 `linux/arm64` (맥이 자기 아키텍처 버전을 받았다는 증거)

## 미션 4 · Secret 마스킹 관찰 (안전하게)

## 미션 5 · PR에는 정말 push가 안 되는지 확인

**배우는 것:** `if: github.event_name != 'pull_request'` 가드가 실제로 동작하는가

### ① 브랜치 만들고 사소한 변경 → PR

```bash
git checkout -b test/05-pr-guard
perl -pi -e 's/더치페이 계산기/더치페이 계산기 (PR 테스트)/' 04-docker-build/app/src/index.js

gh pr create --title "테스트: 5회차 PR 가드 확인" --body "미션5 - push/login step이 PR에서 skip되는지 확인" --base main
```

### ② PR의 체크 확인

```bash

PR_RUN_ID="$(gh run list --workflow 05-docker-push.yml -L1 --json databaseId -q '.[0].databaseId')"
```

```bash
git pull origin main
```

merge 커밋은 `main` 에 `push` 이벤트를 발생시키니, 이번엔 로그인/push가 **다시 실행**된다 — 필요하면 확인.

## 미션 1 · 다차원 매트릭스 (`os × node-version`)

**배우는 것:** 매트릭스 축 2개 조합, job 이름에 매트릭스 값이 자동으로 붙는 것

### ① 파일 작성

```bash
cd ~/Workspace/CICD-study
mkdir -p .github/workflows
cat > .github/workflows/08-advanced.yml <<'EOF'
name: 08 - Advanced

on:
  push:
    branches:
      - main
      - develop
  workflow_dispatch:

jobs:
  test:
    strategy:
      matrix:
        os: [ubuntu-latest, macos-latest]
        node-version: [18, 20, 22]
    runs-on: ${{ matrix.os }}
    defaults:
      run:
        working-directory: 03-auto-test/app
    steps:
      - name: 코드 체크아웃
        uses: actions/checkout@v4

      - name: Node.js 설치
        uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
          cache: npm
          cache-dependency-path: 03-auto-test/app/package-lock.json

      - name: 의존성 설치
        run: npm ci

      - name: 테스트 실행
        run: npm test
EOF
```

### ② 커밋 & push

```bash
git add .github/workflows/08-advanced.yml
git commit -m "8회차 미션1: os x node-version 다차원 매트릭스"
git push origin main
```

### ③ 실행 결과 확인 — job이 6개 생기는지

```bash
sleep 8
RUN_ID="$(gh run list --workflow 08-advanced.yml -L1 --json databaseId -q '.[0].databaseId')"
gh run watch "$RUN_ID"
gh run view "$RUN_ID" --json jobs -q '.jobs[] | {name, conclusion}'
```

**확인 포인트**
- [ ] job이 총 6개 (`ubuntu-latest`/`macos-latest` × `18`/`20`/`22`)
- [ ] 각 job 이름이 `test (ubuntu-latest, 18)` 처럼 매트릭스 값을 포함
- [ ] 전부 `success`

## 미션 2 · `exclude` + `fail-fast` 실험

**배우는 것:** 특정 조합 제외, `fail-fast` 기본값(`true`)의 실제 동작(취소), `fail-fast: false`와의 차이

### ① 파일 수정 — `exclude` 추가

```bash

name: 08 - Advanced

on:

    branches:

jobs:
  test:
    strategy:
      matrix:
        os: [ubuntu-latest, macos-latest]
        node-version: [18, 20, 22]
        exclude:
          - os: macos-latest
            node-version: 18
    runs-on: ${{ matrix.os }}
    defaults:
      run:
        working-directory: 03-auto-test/app
    steps:
      - name: 코드 체크아웃

      - name: Node.js 설치
        uses: actions/setup-node@v4
        with:

      - name: 테스트 실행
        run: npm test
EOF

git add .github/workflows/08-advanced.yml
git commit -m "8회차 미션2: macos+node18 조합 exclude"
git push origin main
```

### ② 확인 — job이 5개로 줄었는지

- [ ] job이 5개 (`macos-latest, 18` 조합이 없음)

### ③ 일부러 테스트를 깨뜨려서 `fail-fast` 기본 동작(취소) 관찰

```bash

git add 03-auto-test/app/src/money.js

```

**확인 포인트**
- [ ] 적어도 하나는 `failure`
- [ ] 나머지 중 일부(또는 전부)가 `cancelled` — 보통 `macos-latest`가 대기열/부팅이 더 오래 걸려서
      `ubuntu-latest` 쪽이 먼저 실패 → 아직 안 끝난 macOS job이 취소됨

<details><summary>힌트: 전부 failure로만 나온다면</summary>

취소가 일어나려면 "먼저 실패하는 job"과 "그때 아직 안 끝난 job"이 동시에 있어야 한다. GitHub 러너
큐 상황에 따라 이번엔 전부 거의 동시에 끝나서 취소가 안 일어날 수도 있다 — 인프라 타이밍이라 100%
재현이 보장되진 않는다. `conclusion` 목록에 `cancelled`가 하나도 없다면 그냥 이번엔 다 비슷한
속도로 끝난 것으로 이해하고 다음 단계로 넘어가면 된다.
</details>


## 미션 3 · `actions/cache`로 `node_modules` 직접 캐싱

**배우는 것:** `key`/`restore-keys`/`hashFiles`, `cache-hit` 출력값의 의미(정확 일치 vs 부분 복원)

### ① 파일 수정 — `setup-node`의 `cache: npm` 대신 `actions/cache` 직접 사용

```bash
cat > .github/workflows/08-advanced.yml <<'EOF'
name: 08 - Advanced

on:
  push:
    branches:
      - main
      - develop
  workflow_dispatch:

jobs:
  test:
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, macos-latest]
        node-version: [18, 20, 22]
        exclude:
          - os: macos-latest
            node-version: 18
    runs-on: ${{ matrix.os }}
    defaults:
      run:
        working-directory: 03-auto-test/app
    steps:
      - name: 코드 체크아웃
        uses: actions/checkout@v4

      - name: Node.js 설치
        uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}

      - name: node_modules 캐시
        id: cache-node-modules
        uses: actions/cache@v4
        with:
          path: 03-auto-test/app/node_modules
          key: node-modules-${{ matrix.os }}-${{ matrix.node-version }}-${{ hashFiles('03-auto-test/app/package-lock.json') }}
          restore-keys: |
            node-modules-${{ matrix.os }}-${{ matrix.node-version }}-

      - name: 캐시 hit 여부 출력
        run: echo "cache-hit=${{ steps.cache-node-modules.outputs.cache-hit }}"

      - name: 의존성 설치
        if: steps.cache-node-modules.outputs.cache-hit != 'true'
        run: npm ci

      - name: 테스트 실행
        run: npm test
EOF

git add .github/workflows/08-advanced.yml
git commit -m "8회차 미션3: actions/cache로 node_modules 직접 캐싱"
git push origin main
```

### ② 첫 실행 — 캐시 미스 확인 (이 key로는 처음이라 캐시가 없음)

```bash

gh run watch "$RUN_ID"
gh run view "$RUN_ID" --json jobs -q '.jobs[] | select(.name | contains("ubuntu-latest, 20")) | .steps[] | {name, conclusion}'
```

**확인 포인트**
- [ ] `캐시 hit 여부 출력` 로그에 `cache-hit=false` (또는 빈 값)
- [ ] `의존성 설치` step이 `success`로 **실행됨**

### ③ 아무것도 안 바꾸고 다시 push — 캐시 히트 확인



      `restore-keys`로 이전 캐시를 부분 복원은 했지만 완전 일치가 아니므로 `false`)

## 미션 4 · 실패 시 GitHub 이슈 자동 생성

**배우는 것:** `needs` + `if: failure()`, `actions/github-script`, `context` 객체

### ① 파일 수정 — `notify-on-failure` job 추가

```bash
cat > .github/workflows/08-advanced.yml <<'EOF'
name: 08 - Advanced

on:
  push:
    branches:
      - main
      - develop
  workflow_dispatch:

jobs:
  test:
    strategy:
      fail-fast: false

        os: [ubuntu-latest, macos-latest]
        node-version: [18, 20, 22]
        exclude:
          - os: macos-latest
            node-version: 18
    runs-on: ${{ matrix.os }}
    defaults:
      run:
        working-directory: 03-auto-test/app
    steps:
      - name: 코드 체크아웃
        uses: actions/checkout@v4

      - name: Node.js 설치
        uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}

      - name: node_modules 캐시
        id: cache-node-modules
        uses: actions/cache@v4
        with:
          path: 03-auto-test/app/node_modules
          key: node-modules-${{ matrix.os }}-${{ matrix.node-version }}-${{ hashFiles('03-auto-test/app/package-lock.json') }}

              owner: context.repo.owner,
              repo: context.repo.repo,
              title: `🚨 CI 실패: ${context.workflow} #${context.runNumber}`,
              body: `test job이 실패했습니다.\n\n[실행 로그 보기](${context.serverUrl}/${context.repo.owner}/${context.repo.repo}/actions/runs/${context.runId})`
```

## 도전 미션 (선택) · `$GITHUB_STEP_SUMMARY`로 매트릭스 결과 요약

**배우는 것:** step 요약 파일에 마크다운 기록, `if: always()`가 필요한 이유

> 이 기능은 Actions 탭 **브라우저 화면**에서만 확인 가능하다 (`gh` CLI로 요약 내용 자체를 조회하는
> API는 없다). 브라우저를 열어서 직접 확인해보자.

### ① 파일 수정 — `test` job에 요약 기록 step 추가

```bash
cat > .github/workflows/08-advanced.yml <<'EOF'
name: 08 - Advanced

on:
  push:
    branches:
      - main
      - develop
  workflow_dispatch:

jobs:
  test:
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, macos-latest]
        node-version: [18, 20, 22]
        exclude:
          - os: macos-latest
            node-version: 18
    runs-on: ${{ matrix.os }}
    defaults:
      run:
        working-directory: 03-auto-test/app
    steps:
      - name: 코드 체크아웃
        uses: actions/checkout@v4

      - name: Node.js 설치
        uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}

      - name: node_modules 캐시
        id: cache-node-modules
        uses: actions/cache@v4
        with:
          path: 03-auto-test/app/node_modules
          key: node-modules-${{ matrix.os }}-${{ matrix.node-version }}-${{ hashFiles('03-auto-test/app/package-lock.json') }}
          restore-keys: |
            node-modules-${{ matrix.os }}-${{ matrix.node-version }}-

      - name: 의존성 설치
        if: steps.cache-node-modules.outputs.cache-hit != 'true'
        run: npm ci

      - name: 테스트 실행
        run: npm test

      - name: 결과 요약 기록
        if: always()
        run: |
          echo "- ${{ matrix.os }} / node ${{ matrix.node-version }}: ${{ job.status }}" >> "$GITHUB_STEP_SUMMARY"

  notify-on-failure:
    needs: test
    if: failure()
    runs-on: ubuntu-latest
    steps:
      - name: 실패 이슈 자동 생성
        uses: actions/github-script@v7
        with:
          script: |
            await github.rest.issues.create({
              owner: context.repo.owner,
              repo: context.repo.repo,
              title: `🚨 CI 실패: ${context.workflow} #${context.runNumber}`,
              body: `test job이 실패했습니다.\n\n[실행 로그 보기](${context.serverUrl}/${context.repo.owner}/${context.repo.repo}/actions/runs/${context.runId})`
```

## 미션 1 · Dockerfile 작성하고 로컬에서 빌드·실행

**배우는 것:** `FROM/WORKDIR/COPY/RUN`, `ENTRYPOINT` vs `CMD`, `docker build`, `docker run`, 종료 코드

### ① 파일 작성

```bash
cat > 04-docker-build/app/Dockerfile <<'EOF'
FROM node:20-slim

WORKDIR /app

# 의존성 매니페스트만 먼저 복사 (레이어 캐시용)
COPY package.json package-lock.json ./
RUN npm ci --omit=dev

# 나머지 소스 복사
COPY . .

# 항상 실행되는 부분(ENTRYPOINT) + 기본 인자(CMD) 분리
ENTRYPOINT ["node", "src/index.js"]
CMD ["30000", "4"]
EOF
```

> `docker run <이미지> 17000 3` 처럼 인자를 주면 **`CMD` 부분만 통째로 교체**되고 `ENTRYPOINT` 는 그대로다.
> → `node src/index.js 17000 3` 실행.
> 만약 `CMD ["node","src/index.js"]` 한 줄로만 두면, `docker run <이미지> 17000 3` 이 그 줄을 통째로 지우고
> 베이스 이미지가 `node 17000 3` 을 실행해 `Cannot find module '/app/17000'` 로 터진다.

### ② 로컬 빌드 & 실행 (아직 커밋 X)

```bash
# 저장소 루트에서. 마지막 인자가 "빌드 컨텍스트"
docker build -t cicd-study-sample:local ./04-docker-build/app

# 이미지 확인
docker images cicd-study-sample

# 컨테이너 실행 (CMD 의 기본 인자 30000 4 사용)
docker run --rm cicd-study-sample:local
echo "종료 코드: $?"

# 인자를 주면 CMD(기본 인자)만 교체됨 → node src/index.js 17000 3
docker run --rm cicd-study-sample:local 17000 3
```

**확인 포인트**
- [ ] `docker build` 마지막 줄이 `naming to ... cicd-study-sample:local` (성공)
- [ ] `docker run` 출력에 `=== 더치페이 계산기 (Docker) ===` 와 `1인당 : 7,500원` (30000/4)
- [ ] 종료 코드가 `0`
- [ ] 인자 `17000 3` 을 주면 `1인당 : 5,667원` (5666.6… → 올림)

<details><summary>힌트: build 로그 읽는 법</summary>

각 `=> [n/n] RUN/COPY ...` 줄이 레이어 하나. `CACHED` 표시가 붙으면 재사용된 것.
첫 빌드는 `node:20-slim` 을 받느라(`=> => transferring`) 시간이 좀 걸립니다.
</details>

## 미션 2 · `.dockerignore` 추가하고 레이어 캐시 관찰

**배우는 것:** 빌드 컨텍스트 줄이기, "소스만 바꾸면 `npm ci` 레이어는 CACHED"

### ① 파일 작성

```bash
cat > 04-docker-build/app/.dockerignore <<'EOF'
node_modules
.git
Dockerfile
.dockerignore
*.log
EOF
```

### ② 캐시 동작 실험 (로컬)

```bash
# 1) 방금 만든 .dockerignore 적용해서 다시 빌드 → 대부분 CACHED
docker build -t cicd-study-sample:local ./04-docker-build/app

# 2) 소스 한 줄만 바꿔본다
perl -pi -e 's/더치페이 계산기/더치페이 계산기 v2/' 04-docker-build/app/src/index.js

# 3) 다시 빌드 → npm ci 레이어는 CACHED, COPY . . 아래만 다시 실행
docker build -t cicd-study-sample:local ./04-docker-build/app
docker run --rm cicd-study-sample:local

# 4) 원상복구
git checkout 04-docker-build/app/src/index.js
```

**확인 포인트**
- [ ] 2번째 빌드(1단계)에서 `COPY package.json ...` 와 `RUN npm ci` 줄에 `CACHED`
- [ ] 소스만 바꾼 3번째 빌드에서도 `RUN npm ci` 는 여전히 `CACHED`, `COPY . .` 부터 다시 실행됨
- [ ] (반대로) `04-docker-build/app/package.json` 을 건드리면 `npm ci` 부터 다시 빌드된다 — 원리 확인만, 실제로 바꾸진 말 것

### ③ 커밋 & push (Dockerfile + .dockerignore)

```bash
git add 04-docker-build/app/Dockerfile 04-docker-build/app/.dockerignore
git commit -m "4회차 미션1-2: Dockerfile + .dockerignore"
git push origin main
```

## 미션 3 · CI에서 이미지 자동 빌드 (push 안 함)

**배우는 것:** `docker/setup-buildx-action`, `docker/build-push-action` (`push: false`, `load: true`)

### ① 파일 작성

```bash
mkdir -p .github/workflows
cat > .github/workflows/04-docker.yml <<'EOF'
name: 04 - Docker Build

on:
  workflow_dispatch:
  push:
    paths:
      - "04-docker-build/app/**"
      - ".github/workflows/04-docker.yml"
  pull_request:
    paths:
      - "04-docker-build/app/**"
      - ".github/workflows/04-docker.yml"

jobs:
  docker-build:
    runs-on: ubuntu-latest
    steps:
      - name: 코드 체크아웃
        uses: actions/checkout@v4

      - name: Buildx 준비
        uses: docker/setup-buildx-action@v3

      - name: 이미지 빌드 (push 안 함)
        uses: docker/build-push-action@v6
        with:
          context: ./04-docker-build/app
          push: false
          load: true
          tags: cicd-study-sample:latest
EOF
```

### ② 커밋 & push

```bash
git add .github/workflows/04-docker.yml
git commit -m "4회차 미션3: CI에서 Docker 이미지 빌드 (push X)"
git push origin main
```

### ③ 실행 & 확인

```bash
sleep 5
RUN_ID="$(gh run list --workflow 04-docker.yml -L1 --json databaseId -q '.[0].databaseId')"
gh run watch "$RUN_ID"
gh run view "$RUN_ID" --log
```

**확인 포인트**
- [ ] job `docker-build` 가 `success`
- [ ] 로그에 `Buildx 준비` step 에서 buildx 빌더가 만들어짐
- [ ] `build-push-action` 로그에 `exporting to docker` / `importing to docker` (= `load: true` 효과)
- [ ] `push` 관련 로그가 **없다** (레지스트리로 안 올림)

## 미션 4 · 빌드된 이미지로 스모크 테스트

**배우는 것:** "빌드 성공 ≠ 실행 성공" → `docker run` 으로 검증

### ① 파일 작성 (덮어쓰기) — 마지막에 step 추가

```bash
cat > .github/workflows/04-docker.yml <<'EOF'
name: 04 - Docker Build

on:
  workflow_dispatch:
  push:
    paths:
      - "04-docker-build/app/**"
      - ".github/workflows/04-docker.yml"
  pull_request:
    paths:
      - "04-docker-build/app/**"
      - ".github/workflows/04-docker.yml"

jobs:
  docker-build:
    runs-on: ubuntu-latest
    steps:
      - name: 코드 체크아웃
        uses: actions/checkout@v4

      - name: Buildx 준비
        uses: docker/setup-buildx-action@v3

      - name: 이미지 빌드 (push 안 함)
        uses: docker/build-push-action@v6
        with:
          context: ./04-docker-build/app
          push: false
          load: true
          tags: cicd-study-sample:latest

      - name: 스모크 테스트 (컨테이너 실행)
        run: |
          docker run --rm cicd-study-sample:latest 30000 4 | tee out.txt
          grep "1인당" out.txt
EOF
```

### ② 커밋 & push

```bash
git add .github/workflows/04-docker.yml
git commit -m "4회차 미션4: 빌드 이미지 스모크 테스트"
git push origin main
```

### ③ 실행 & 확인

```bash
sleep 5
RUN_ID="$(gh run list --workflow 04-docker.yml -L1 --json databaseId -q '.[0].databaseId')"
gh run watch "$RUN_ID"
gh run view "$RUN_ID" --log | grep -A5 "스모크"
```

**확인 포인트**
- [ ] `스모크 테스트` step 로그에 `1인당 : 7,500원` 이 찍힌다
- [ ] `grep "1인당"` 이 매칭돼서 step 이 `success` (매칭 실패하면 grep 이 exit 1 → step 실패)

## 미션 5 · Dockerfile 을 일부러 깨뜨려 CI 실패 관찰

**배우는 것:** 빌드 단계 실패가 파이프라인을 어떻게 멈추는가 / 로그로 원인 찾기

### ① 존재하지 않는 파일을 COPY 하도록 수정

```bash
perl -pi -e 's{COPY \. \.}{COPY nope.txt ./}' 04-docker-build/app/Dockerfile
git add 04-docker-build/app/Dockerfile
git commit -m "4회차 미션5: (일부러) 잘못된 COPY 로 빌드 깨기"
git push origin main
```

### ② 실행 & 확인

```bash
sleep 5
RUN_ID="$(gh run list --workflow 04-docker.yml -L1 --json databaseId -q '.[0].databaseId')"
gh run watch "$RUN_ID" || true
gh run view "$RUN_ID" --log-failed
```

**확인 포인트**
- [ ] `이미지 빌드` step 에서 실패 — 로그에 `"/nope.txt": not found` 류 메시지
- [ ] 그 **뒤의 `스모크 테스트` step 은 실행되지 않음** (skip)
- [ ] job `conclusion` = `failure`

### ③ 원상복구 (revert)

```bash
git revert --no-edit HEAD
git push origin main

sleep 5
RUN_ID="$(gh run list --workflow 04-docker.yml -L1 --json databaseId -q '.[0].databaseId')"
gh run watch "$RUN_ID"
```

- [ ] revert 후 다시 `success`

## 미션 6 · GitHub Actions 캐시(`type=gha`)로 빌드 가속

**배우는 것:** 러너가 매번 새 VM이라도 레이어 캐시를 실어 나르기

### ① 파일 작성 (덮어쓰기) — build step 에 캐시 2줄 추가

```bash
cat > .github/workflows/04-docker.yml <<'EOF'
name: 04 - Docker Build

on:
  workflow_dispatch:
  push:
    paths:
      - "04-docker-build/app/**"
      - ".github/workflows/04-docker.yml"
  pull_request:
    paths:
      - "04-docker-build/app/**"
      - ".github/workflows/04-docker.yml"

jobs:
  docker-build:
    runs-on: ubuntu-latest
    steps:
      - name: 코드 체크아웃
        uses: actions/checkout@v4

      - name: Buildx 준비
        uses: docker/setup-buildx-action@v3

      - name: 이미지 빌드 (push 안 함)
        uses: docker/build-push-action@v6
        with:
          context: ./04-docker-build/app
          push: false
          load: true
          tags: cicd-study-sample:latest
          cache-from: type=gha
          cache-to: type=gha,mode=max

      - name: 스모크 테스트 (컨테이너 실행)
        run: |
          docker run --rm cicd-study-sample:latest 30000 4 | tee out.txt
          grep "1인당" out.txt
EOF
```

### ② 커밋 & push → 두 번 실행

```bash
git add .github/workflows/04-docker.yml
git commit -m "4회차 미션6: type=gha 빌드 캐시"
git push origin main

# 1회차 실행 (캐시 생성)
sleep 5
RUN_ID="$(gh run list --workflow 04-docker.yml -L1 --json databaseId -q '.[0].databaseId')"
gh run watch "$RUN_ID"

# 2회차 실행 — 소스/의존성 안 바꾸고 수동 트리거
gh workflow run 04-docker.yml --ref main
sleep 5
RUN_ID2="$(gh run list --workflow 04-docker.yml -L1 --json databaseId -q '.[0].databaseId')"
gh run watch "$RUN_ID2"
gh run view "$RUN_ID2" --log | grep -Ei "cache|CACHED" | head -30
```

**확인 포인트**
- [ ] 1회차 로그 끝에 `exporting cache to gha` (또는 `ExportCache`)
- [ ] 2회차 로그에 `importing cache` + `RUN npm ci` 등 레이어에 `CACHED`
- [ ] 2회차 빌드 step 소요 시간이 1회차보다 눈에 띄게 짧다 (`gh run view --json jobs` 의 step timing)

## 도전 미션 (선택) · 멀티스테이지로 이미지 줄이기 + sha 태그

> 8회차(심화) 예고편. 건너뛰어도 됩니다.

### A. 커밋 SHA 태그 추가

`tags:` 를 여러 줄로:

```yaml
          tags: |
            cicd-study-sample:latest
            cicd-study-sample:${{ github.sha }}
```

push 후 `gh run view "$RUN_ID" --log | grep sha256 -n` 없이도, build 로그의 `naming to` 줄에 태그 2개가 보이는지 확인.

### B. 멀티스테이지 빌드 (로컬 비교)

```bash
cat > 04-docker-build/app/Dockerfile.multi <<'EOF'
# --- build 단계: 의존성 설치 ---
FROM node:20-slim AS build
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci --omit=dev
COPY . .

# --- runtime 단계: 결과물만 옮김 ---
FROM node:20-slim
WORKDIR /app
COPY --from=build /app ./
CMD ["node", "src/index.js"]
EOF

docker build -t cicd-study-sample:single -f 04-docker-build/app/Dockerfile       ./04-docker-build/app
docker build -t cicd-study-sample:multi  -f 04-docker-build/app/Dockerfile.multi ./04-docker-build/app
docker images cicd-study-sample
```

**확인 포인트**
- [ ] 이 앱은 의존성이 없어 크기 차이가 작다 — 원리만 확인 (dev 도구/빌드 산출물이 많은 프로젝트일수록 효과 큼)
- [ ] `docker history cicd-study-sample:multi` 로 레이어 구성 비교

정리 후:
```bash
rm 04-docker-build/app/Dockerfile.multi   # 도전용 파일은 커밋 안 함 (원하면 커밋해도 됨)
docker image rm cicd-study-sample:single cicd-study-sample:multi cicd-study-sample:local 2>/dev/null || true
```
